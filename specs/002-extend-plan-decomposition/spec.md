# Extend Plan Decomposition

## Problem Statement

**Pain Point**: The trasgospec preset overrides the entire plan command via a custom SKILL.md to get Capability Tree, Journey Contracts, and Structural Decomposition in the generated plan. This override bypasses the default command's Phase 0/Phase 1 workflow (research.md, data-model.md, contracts/, quickstart.md), creating a maintenance burden and divergence from upstream spec-kit. The preset should extend the default, not replace it.

## Who

- **Trasgospec preset maintainer** — maintains the preset and wants to stay aligned with the default spec-kit plan command while adding the three decomposition sections via the template layer.

## Current Alternatives

The preset ships a full command override (`preset/commands/speckit.plan.md`) that replaces the default workflow with a custom a-g section list. This works but means any upstream improvements to the default plan command don't flow through automatically.

## Desired Outcome

The preset drops its plan command override and falls back to the default spec-kit command. The preset's `plan-template.md` extends the default template by appending Capability Tree, Journey Contracts, and Structural Decomposition sections. The default command's "follow the template" instruction fills these additional sections alongside its standard Phase 0/Phase 1 workflow.

## Jobs to Be Done

- When I move from spec to plan, I want journey contracts with tier/setup/action/assert in the preset's plan template, so the tasks command can scaffold BDD/TDD phases automatically.
- When I plan implementation, I want a structural decomposition with NEW/MODIFIED annotations in the preset's plan template, so agents know where to create or modify files.
- When the default spec-kit command improves, I want those improvements to flow into the preset automatically, so I don't maintain a separate command override.

## User Journeys

- **J1**: Given a spec.md with numbered user journeys (J1, J2...), when the default plan command fills the preset's template, then the Capability Tree section lists features with "Supports" fields referencing journey IDs.

- **J2**: Given a spec.md with numbered user journeys, when the default plan command fills the preset's template, then every journey ID has a Journey Contract with Tier, Setup, Action, and Assert fields.

- **J3**: Given a spec.md with defined capabilities, when the default plan command fills the preset's template, then the Structural Decomposition section includes a repository structure tree with NEW/MODIFIED annotations and module definitions with exports.

- **J4**: Given the preset command override is removed, when a user runs the plan command, then the default spec-kit command executes (Phase 0/Phase 1) and also fills the three appended template sections.

## Assumptions

1. All changes are in the trasgo-speckit preset — no modifications to the spec-kit repo.
2. The default plan command's "follow the template" instruction is sufficient to fill appended sections with `<instruction>` blocks.
3. Existing Phase 0/Phase 1 artifacts (research.md, data-model.md, contracts/, quickstart.md) continue to be generated by the default command.
4. The preset's plan-template.md is based on the default spec-kit template with the three sections appended.
